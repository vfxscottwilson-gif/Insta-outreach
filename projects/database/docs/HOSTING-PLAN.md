# Hosting plan: Database dashboard online, free (researched 2026-11-05)

Sources and per-claim checks: `archive/research-raw/hosting-research.json`. Not legal or financial advice.

## Decision
Run the Database app exactly as it is on your own Windows PC and put Cloudflare Tunnel in front of it. Cloudflare then gives you a fixed https:// address (for example https://db.your-domain.com) that works on iPhone, Android, Windows and Mac, with a valid certificate, no router changes and no code rewrite. The tunnel is free on every Cloudflare plan (checked against Cloudflare's blog, the Tunnel docs and a July 2026 third-party article, 2026-11-05), needs no card, and Claude can do almost every step once you are signed in. The one real catch: the site and the 2-minute Google Sheets scan only work while your PC is on, awake and online; if the PC sleeps or is off, visitors see Cloudflare error 1033 until it is back, nothing on disk is lost. The one unavoidable cost is a domain name on Cloudflare (about $10.5 to $11.2 per year for a .com), which is $0 if you already have a domain on your Cloudflare account from the other app. If you later want it up 24/7 without the PC, the fallback is an Oracle Cloud Always Free Linux VM (truly $0 but needs a credit card and has an idle-reclaim risk) reusing the same tunnel setup.

## Cloudflare answer
No, the app cannot run ON Cloudflare Pages or Workers for free, and Claude cannot deploy it there. Pages serves static files and Workers run short request-scoped code in V8 or WebAssembly: there is no persistent disk for the SQLite file, no waitress process, and no background thread for the 2-minute scanner (Python Workers document threading as "importable but not functional"). Cloudflare Containers could run it but needs the $5/month Workers Paid plan, has an ephemeral disk that resets, and sleeps after 10 minutes (3 sources, 2026-11-05). The right Cloudflare piece is Cloudflare Tunnel: free on all plans, outbound-only from your PC, Cloudflare terminates HTTPS and forwards to http://127.0.0.1:8080. It needs (a) a Cloudflare account, (b) a domain whose DNS is on Cloudflare (Free plan requires full nameserver setup; a free third-party subdomain does not work), (c) cloudflared installed as a Windows service on the PC. Optional second lock: Cloudflare Access (Zero Trust Free, up to 50 users) adds an email one-time-PIN login in front of the app; it is $0 but Zero Trust signup asks for a payment method on file (docs plus 3 sources), so skip it if you want no card on the account.

## Code and config changes (build chat)
- dash/authz.py: DASH_IDLE_HOURS read lazily after load_env (current .env value is ignored)
- dash/__init__.py + authz.start_session: session.permanent=True, PERMANENT_SESSION_LIFETIME about 30 days, keep 12 h idle logout
- dash/__init__.py HEADERS: Strict-Transport-Security max-age=31536000 when cfg.cookie_secure
- dash/serve.py: trusted_proxy="127.0.0.1", trusted_proxy_headers={"x-forwarded-proto"} so Flask sees https
- dash/db.py connect(): PRAGMA busy_timeout=30000 and synchronous=NORMAL
- Per-IP throttle on /login, /admin/login, /forgot, /reset keyed on CF-Connecting-IP
- PWA: dash/static/manifest.json, PNG icons 192/512/maskable 512/apple-touch 180 from logo.svg, 5 head tags in dash/templates/base.html (manifest link with crossorigin=use-credentials); no service worker
- install/service-run.cmd (no pause/browser, PYTHONUTF8=1) and install/install-service.cmd (Task Scheduler at startup, restart on failure) plus daily manage.py backup task
- Config only, owner edits .env: DASH_COOKIE_SECURE=on
- Tests: manifest link present, manifest parses with 192/512 icons, HSTS only when secure, idle hours from .env

## Hardening before staff use it
- DASH_COOKIE_SECURE=on, HSTS header, share only the https hostname (never the http://localhost one)
- Unique 16+ character passwords for owner and admins; owner's Gmail protected with 2-step verification (whoever controls the mailbox can reset the owner); confirm no demo account in the real DB and never run serve --demo
- Per-IP login throttle in the app (build step 6) plus one Cloudflare WAF rate-limiting rule on /login, /admin/login, /forgot, /reset (Free plan: 1 rule, IP only, 10 s window)
- Optional but recommended: Cloudflare Access (email one-time PIN) in front of at least /admin/*, ideally the whole site, as the missing 2FA; requires a payment method on the Zero Trust account (not charged on Free)
- Run the app task under a limited Windows account, bind stays 127.0.0.1, no router port forwarding; restrict .env and service_account.json file permissions to that account
- PC: never sleep on AC, auto-start at boot, Windows auto-update on, daily stripped backup (manage.py backup) to another disk, test one restore (database/RESTORE.md); never upload backups/backup.ps1 output (contains secrets)
- Keep Cloudflare script-injecting features off (email obfuscation, Web Analytics beacon, Rocket Loader) to avoid breaking the strict CSP
- Test from a phone on mobile data: login, wrong-password lockout, logout, Add to Home Screen, relaunch

## Risks and not verified
- PC must be on 24/7: sleep, shutdown, Windows Update reboot, power or internet loss = site shows Cloudflare error 1033 and the 2-minute Sheets scan pauses (no data lost). Whether the scanner catches up on missed rows after hours offline: not tested.
- Domain cost: Cloudflare's own page shows no price; $10.46/yr .com comes from third-party trackers (dated 2026-10-20 and 2026-11-04) and about $11.15 to $11.17 after Verisign's 2026-11-01 wholesale rise is derived, not seen at checkout. Partly verified.
- Whether creating a tunnel under Networking > Tunnels forces Zero Trust onboarding with a payment method: not verified. Only Zero Trust/Access signup is documented as asking for payment details (not charged on Free).
- Cloudflare Tunnel 'free, no bandwidth cap': 3 sources (2021 blog, Tunnel docs 'Available on all plans', Jul 2026 article) but the full Self-Serve Subscription Agreement was not read end to end.
- cloudflared auto-start after reboot rests on its open-source windows_service.go (StartAutomatic, 20 s restart on failure); confirm with 'sc qc cloudflared' after install.
- Public login today has no per-IP throttle and no 2FA; anyone knowing the owner's email can keep locking that account (5 wrong tries per 5 min). The build chat adds a per-IP throttle; Cloudflare Access is the optional 2FA.
- Bug found: DASH_IDLE_HOURS in .env is ignored (authz.py reads os.environ at import before .env loads); proven in a scratch copy only. Fix included in the build message.
- PWA: no manifest, PNG icons or apple-touch-icon exist today; nothing was installed on a real iPhone/Android/Mac. iOS Home Screen app has a separate cookie jar from Safari (WebKit bug 272325 reports session cookies resetting on iOS 17.2 to 18.1); persistent 30-day cookie is the planned mitigation, not confirmed.
- Cloudflare Access in front of a PWA (manifest/service worker fetch redirected to the Access login) not tested; crossorigin=use-credentials on the manifest link is the known fix. Cloudflare auto-injected scripts (email obfuscation, analytics beacon, Rocket Loader) vs the app's strict CSP: not tested; leave them off.
- Oracle fallback: idle-reclaim exemption after upgrading to Pay As You Go is quoted from Oracle emails by third parties, not in Oracle docs; outbound SMTP 587 from Oracle not documented; card acceptance (prepaid/virtual rejected) not predictable.
- Test suite was not run by the researchers (CLAUDE.md says 390 pass, GUIDE says 327, 338 test defs found). Real Google Sheets API path is marked 'NOT verified' in sources.py itself.
- Dashboard image preview: not produced in this decision step.
