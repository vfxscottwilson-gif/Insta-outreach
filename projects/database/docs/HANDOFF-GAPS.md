## 3. State machines
**Lead lifecycle** (`leads.state` derived from columns: `removed`, `trashed_at`, `purged_at`)
`active` -> (employee/admin "Request removal") -> `pending` (removal_requests) -> admin Approve -> `trashed` (30 d, `settings.trash_days`) -> admin Purge (typed confirm: count + sheet label) -> `purged` (anonymised, tombstone). Reject -> `active`. Restore from `trashed` -> `active` (admin, audited).
`missing` (absent from 2 complete sweeps) -> Approvals "Missing in source": Keep (`miss_count=0`) / Confirm removal (-> `trashed`). Breaker -> single sheet-level item.
Who: request = any role on a visible lead; approve/reject/purge/restore = either admin (owner or second; decided 2026-11-04); retention days, auto-purge = owner only (#16). Enforced in: route decorators (`admin_required`/`owner_required`), plus `visible_leads_sql`, not templates. Employees cannot DELETE; no route deletes lead rows.
**Reached**: `none` -> `reached` (sticky) via (a) `POST /leads/<id>/contacted` (any role, visible lead, audited), (b) sheet Status seen moving to Contacted / Follow-up 1 / Follow-up 2 / Replied / Call booked / Client AFTER first import (observed time). Rows already past New at first import -> bucket `reached_before_tracking`. Tile label shows source + "last reach event N days ago"; no source -> "Not tracked yet", never 0. Waiting = usable AND Status in (blank, New) AND no reach event. Enforced in `stats` query helpers.
**Tombstone**: created at Purge and at hard "Confirm removal"; `sync._store` + add/paste skip any `(source_id,key)` or `email_hash` present; nothing deletes tombstones.
**Do not contact**: set by any role on a visible lead -> `dnc_at`, excluded at once from Usable, Waiting, assign, export (`WHERE dnc_at IS NULL`); with write-back ON the existing Status path writes "Do not contact" (the bots skip it, RC LB fact 10); with write-back OFF the owner gets a to-do "Add key to Blacklist tab of sheet Y" + Copy button. Only an admin can clear it (default).
**Approvals items** (`approvals_items`/`removal_requests`): kinds `removal`, `missing_in_source`, `sheet_vanish`, `employee_batch` (Send to Outreach), later `access_request`; sidebar badge = pending count; either admin decides, with note; audited.
**Trash/purge**: nothing hard-deleted except `contacts` rows of a purged lead; `audit` scrubbed for that lead id. Auto-purge off by default (owner switch).

## 4. Per-sheet access, per-employee dashboard, standing assignment (proposal)
```sql
ALTER TABLE users ADD COLUMN is_owner INTEGER NOT NULL DEFAULT 0;      -- first admin
ALTER TABLE users ADD COLUMN active INTEGER NOT NULL DEFAULT 1;        -- deactivate, never DELETE
CREATE TABLE IF NOT EXISTS settings(key TEXT PRIMARY KEY, value TEXT NOT NULL, changed_by INTEGER, changed_at TEXT);
  -- admin_cap='2' trash_days='30' auto_purge='off' skip_segments='HAS-AGENCY,POLISHED-NO-SIGNAL' daily_add_cap='100'
CREATE TABLE IF NOT EXISTS sheet_access(
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  source_id TEXT NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  level TEXT NOT NULL CHECK(level IN ('hidden','view','contribute')),
  scope TEXT NOT NULL DEFAULT 'assigned' CHECK(scope IN ('all','assigned')),   -- default: assigned only (today's rule)
  can_reveal INTEGER NOT NULL DEFAULT 0, can_export INTEGER NOT NULL DEFAULT 0,
  granted_by INTEGER, granted_at TEXT NOT NULL,
  PRIMARY KEY(user_id, source_id));
CREATE TABLE IF NOT EXISTS assign_rules(            -- standing rule: new leads of a sheet/tab auto-assign
  id INTEGER PRIMARY KEY, source_id TEXT NOT NULL REFERENCES sources(id),
  gid INTEGER, user_id INTEGER NOT NULL REFERENCES users(id),     -- gid NULL = whole sheet
  active INTEGER NOT NULL DEFAULT 1, created_by INTEGER, created_at TEXT NOT NULL, stopped_at TEXT);
ALTER TABLE leads ADD COLUMN assign_note TEXT;       -- reuse due_on, note; status stays sheet vocabulary
```
- Visibility (one function, used everywhere): admin = all; employee = leads of sources where `sheet_access.level IN ('view','contribute')` AND (`scope='all'` OR `assignee_id = me`). `hidden`/no row = invisible. Assignment never grants visibility: `assign` refuses "X has no access to this sheet. Give View access too?" (RT verified; BR s6).
- Migration default: for every employee with assigned leads, insert `sheet_access(level='view', scope='assigned')` per source so nothing disappears.
- Employee dashboard `/my`: assigned count, progress per sheet (reached by anyone / assigned), my sheets + level, my adds (`added_by`), my requests (`removal_requests.requested_by`), my numbers day/week, leads to contact now (#28). Admin sees the same page at `/team/<id>` (`user_id` param). Sheets-per-employee count column on `/team` (`COUNT(sheet_access)`).
- Standing rule created by the Assign dialog checkbox "Also assign new leads that arrive" (default on for whole sheet/tab); list with Stop on `/team`; Needs-you count: `assignee_id IS NULL AND first_seen < now-24h`.
- SQLite note: ALTER ADD COLUMN needs a `schema_version` entry in `meta` + a tiny `migrate()` in `db.connect` (today only `CREATE IF NOT EXISTS`).
