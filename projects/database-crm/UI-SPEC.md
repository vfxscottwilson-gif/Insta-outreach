# Database app: UI spec for the clickable preview (mock data only)

Owner: chat "Database UI: clickable preview". Approval document with the decisions: `BRIEF.md` (read it first). Goal: the user clicks through every screen of the future app, on desktop and phone, in dark and light, and understands the whole workflow. No backend, no secrets, no real data.

## 1. Base and rules

## 2. Roles in the preview
Owner (the signed-in "You"), Admin, Employee. Reuse the shell's "View as" switch (admin-only) so the user can flip to an employee and see the limited app. Employees see only their sheets and assigned leads; screens they cannot use are not in their nav.

## 3. Mock world (use these names so the story is consistent)
Sheets (each = one Google Sheet, tab per niche, plus Stats tab, hidden Meta tab, control tabs): **US Leads**, **CA Leads**, **GB Leads**, **AU Leads**, **NZ Leads**, **IE Leads**, **AE Leads**, **YouTube Creators**, **AU Only (Sydney)**. Roles of tabs: data / dashboard / log / control. Run windows: worldwide 08:00 and 20:00 UTC, AU-only 07:00 and 19:00 UTC. Statuses: On schedule, Running now, Late, Stopped (one sheet late, one with lost access, so every state is visible).
Lead columns (from the real bot): Company Name, Decision Maker Name, Personal Email, Generic Email, Phone, Website, City, State, Country, Country Code, Niche, Niche Group, Segment (PRIME, PRIME-REVIEW, GROWING, HAS-AGENCY, POLISHED-NO-SIGNAL), ICP Score /10 (all 7.0 to 9.8), Tier (A >= 8.5, B >= 7.5, else C), Status (New, Drafted, Contacted, Follow-up 1, Follow-up 2, Replied, Call booked, Client, Not interested, Do not contact), Lead Added On (date), Place Id, plus app fields: first seen (time), assigned to, tags, notes, added by (sheet / manual), missing in source.
~700 leads over 5 weeks, bursts at the run windows; niches such as Dentists, Surgeons, Skin clinics, Real estate, Mortgage brokers, Accountants, Law firms, Wedding venues, Solar, Boutique gyms, YouTube gaming, YouTube fitness (Niche Group above them). 6 people: you (Owner), 1 Admin, 4 Employees (one with View on two sheets, one with Contribute on three, one with an assigned-only scope, one inactive).
Countries with states and IANA time zones (US, CA, AU by state; GB, IE, NZ, AE by country) and Pakistan time shown next to local time.

2. `node scripts/a11y-check.mjs` (adapt to the new routes) and `node scripts/mobile-check.mjs <url> chromium` (320 to 768 px, both orientations) pass; open issues listed in `KNOWN-ISSUES.md`.
3. Screenshots of every screen: dark desktop 1440x900, light desktop, phone 390x844. Plus screenshots of each dialog and the employee view.
4. A script `scripts/preview-tour.mjs` that visits every route as Owner and as Employee, opens each dialog, and fails on any error. Run it and attach the output.
5. Numbers on the Overview must equal what the Leads table filters show for the same range (one shared mock source of truth; add a vitest or script check).
6. Report to the control room: what was built, proof paths, what is not done or not verified.

## 7. Amendments from the red-team review (2026-11-04). These OVERRIDE the rows above where they differ. Full reasoning: `REDTEAM.md`.
1. **Overview**: replace the "automation health list" with ONE compact **Automations table** (same component and query as the Reports per-automation table): per sheet name + status pill, last run and next expected run, leads in the period with delta, emails / names / phones found (count, % in tooltip), reached, "worked by" avatars. A `Segmented` period control above it (Today / This week / This month / Last month). Row click opens `/sheets/$id`; card list on phone. **Remove the "Day basis switch".** Label the Live strip "Pakistan time, arrivals since connect" and the KPI tiles "sheet date". The "Leads today" tile has no delta and a footnote "each sheet's own date".
2. **Reached** (Overview tile, Reports): carries a source label ("app + sheet Status" or "Not tracked yet") and "last reach event N days ago"; a separate "reached before tracking" bucket; a sheet with no reach source shows "Not tracked yet", never 0. Employee progress bars read "assigned leads now reached (by anyone)".
3. **/leads**: add two actions for every role in the drawer and the bulk bar: **Mark contacted** (audited) and **Do not contact** (audited, immediate exclusion, with an owner to-do "Add to the sheet's Blacklist tab" with a Copy button). Remove any "app status" field. Reveal contact is a server call and shows "logged". Add badges "incomplete" and "duplicate in source". Paste import capped at 200 rows; the duplicate check only says "possible duplicate" and never names a sheet the user cannot see; "Also in" lists accessible sheets only.
4. **Mock world**: ICP Score range 5.5 to 9.8, with a few HAS-AGENCY / POLISHED-NO-SIGNAL rows at 5.5 to 6.9 (the bot writes those below 7). Add fields `first_reached_at`, `reached_source` (app / sheet status), `discovery` (live / history), `trashed_at`, `purged_at`.
5. **/sheets wizard and detail**: step 3 shows dropped tabs with the reason ("reserved name", "OLD prefix"); step 2 warns "Shared as Editor, change to Viewer" when the share is Editor; detail page shows per-tab sync state (gid, cursor, last ok, last error), "N tabs failing", rows split active / trashed / purged / missing (they add up to the sheet's rows), and the sheet's Stats heartbeat (Last run, Run health, Dates in time zone).
6. **/quality**: histogram axis 0 to 10; explainer text "bot leads are 7 or more except HAS-AGENCY and POLISHED-NO-SIGNAL"; Average quality and Tier mix default to core segments with an "include side segments" toggle; editable skip-list of segments.
7. **/team and /settings**: an **Owner only** group (admin cap, promote or demote an admin, Trash retention, auto-purge); admins see these controls read-only with the reason. Both admins approve removals stays as the decided rule.
8. **/assignments**: the Assign dialog gets "Also assign new leads that arrive" (default on for a whole sheet or tab), a list of active standing rules with Stop, an "Unassigned" count (Needs you: "N leads unassigned for more than 24 h"), deadline / status / note fields on an assignment, and the refusal "X has no access to this sheet. Give View access too?".
9. **/approvals**: the Approve and Purge dialogs say "Removes it from Database only. The row stays in the Google Sheet (sheet, tab, row). Only you can delete it there."; the Purge typed confirmation includes the lead count and the sheet name; Missing in source gets a bulk Keep all / Confirm all bar and a sheet-level "N rows vanished" item; add a tab **Send to Outreach** (approve a batch of employee-added leads before it goes to the export sheet).
10. **/reports**: the daily report stamps "data as of <time>" and shows "yesterday (complete)" next to "today so far"; schedule stays 20:00 Pakistan time.
11. **/settings Data and Alerts**: Data reads "Backups" and "Report history" (final wording follows the data-plan decision, keep it easy to change); Alerts lists recipients and channels per event (scanner stopped, sheet lost access, do-not-contact not delivered, unassigned over 24 h, capacity 80%) with "Send test".
12. **Strip list** also includes the Outreach `tasks` and `employees` task parts (daily task reports stay in the CRM unless the user says otherwise). Add the Automations table and the Reveal dialog to the dialog list. `BrandMark` keeps the Outreach shine and hover lift so the logo feels alive.
13. **Gate 5** becomes: Overview tiles, Automations table and Leads filters agree for the same range. Add: no real company or contact data in screenshots or proof folders.
